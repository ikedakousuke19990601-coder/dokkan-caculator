# ドカバト 被ダメージ計算ツール 仕様書（MVP）

## 1. アプリ概要

| 項目 | 内容 |
|---|---|
| 名称（仮） | ドカバト 被ダメージ計算ツール |
| 目的 | 敵から受けるダメージだけを計算し、自分のキャラがどのくらい受けるかを確認できるようにする（与ダメージは対象外） |
| ターゲット | ダメージ計算が苦手な初級者（ある程度プレイ経験があり、ゲームの基本用語は理解している） |
| 解決する課題 | 敵の攻撃を自分のキャラがどのくらい受けるかを、ゲームプレイ中でも即座に把握できるようにする |
| 形態 | まずはWebブラウザで動くアプリ。将来的にスマホアプリ化も視野に入れる |
| 前提 | 公式非公開の部分が多いため、コミュニティで知られている計算式に基づく「目安」と明記する |

## 2. 設計方針

- 入力は必要最小限にし、入力に応じてリアルタイムで結果を更新する
- 専門用語の説明は付けない。ラベルはゲーム内の表記に合わせる
- 結果はダメージの数値のみ（内訳・残りHP・判定は出さない）
- 前回の入力をブラウザに保存する
- 計算ロジックはUIから分離した純粋関数にする（将来のスマホアプリ化に備える）
- レスポンシブUI（スマホ幅でも使える）
- 画面に「目安」であることを小さく表示する

## 3. 入力項目

### A. 自分のDEF

| 入力 | 内容 |
|---|---|
| 画面のDEF | 戦闘中にゲーム画面で確認した値（リーダースキル・リンクスキル・現在のパッシブ・フィールド効果込み） |
| これから上がる効果（行を追加できる） | 区分（選択）、追加する％。通常は2項目のみ |
| 反映済みの％（「詳細」を開いたときだけ表示） | 画面のDEFにすでに入っている同じ区分の効果の％（初期値0）。通常は非表示で0として計算する |

#### 区分の選択肢

画面のDEFにはすでに②リーダースキル・③フィールド効果・⑦リンクスキルが入っているため、戦闘中に新しく増えるものだけを選択肢にする。

| 区分 | 表示 | 備考 |
|---|---|---|
| ④-足 | パッシブ（足し算） | 「ターン開始時」など自分の行動が主体でないもの |
| ④-掛 | パッシブ（掛け算） | 「攻撃時」、被弾・回避・ガード・必殺技がトリガーのもの、「ターン終了時」など |
| ⑤ | サポートメモリー・アイテム | |
| ⑥ | アクティブスキル | |
| ⑧ | 必殺技の追加効果 | |

①（DEFステータス値）も「画面のDEF」に含まれるため、選択肢には出さない。

### B. 敵の攻撃

| 入力 | 形式 | 初期値 |
|---|---|---|
| 敵ATK | 数値入力（攻略サイトなどで調べた値を入力する想定。逆算機能は作らない） | 必須 |
| ダメージ軽減率（％） | 数値入力 | 0 |
| 属性防御係数A（属性ガード） | 選択式：なし(1.0) / 0.9 / 0.8 / 0.7 / 0.6 | なし(1.0) |
| 属性防御係数B（全属性ガード） | オン／オフ（オンで0.5） | オフ(1.0) |
| フィールド補正（最終ダメージ） | 数値入力 | 1 |

## 4. 計算式

```
現在DEF = 画面のDEF × Π(区分ごと) (1 + 反映済み% + 追加%の合計) ÷ (1 + 反映済み%)
基本ダメージ(r) = { 敵ATK × r × A × (1 − 軽減率) − 現在DEF } × B × フィールド補正
結果(r) = max(0, 基本ダメージ(r))
```

- 乱数なしの値は r = 1.00、最大乱数の値は r = 1.03 で計算する
- 同じ区分の行が複数ある場合は、追加分を足してから1回だけ掛ける
- 「反映済み％」は、画面のDEFにすでに入っている同じ区分の効果が対象（通常は0）
- ④パッシブは (1 + 足し算パッシブの合計) × (1 + 掛け算パッシブの合計) の2つの別枠

### 端数処理（仮の仕様）

- 途中の計算は都度切り捨て、最終値のみ四捨五入する
- DEFの計算は参考記事に準拠。ダメージ側は記事に明記がなく未確認のため、同じ方針を仮置きしている

## 5. 出力

- 乱数なしの値と最大乱数の値の、2つのダメージ数値のみを表示する
- 入力に応じてリアルタイムで更新する

## 6. MVPに含めないもの

- 属性相性（有利・不利）
- 見切り、気力補正
- キャラ・パッシブのデータベース
- 初期キャラの表記と内部処理が異なる例外
- 計算式の実機検証（MVP後に実施）
- 敵ATKを受けたダメージから逆算する機能

## 7. 未確認・要検証事項

- ダメージ側の端数処理（仮の仕様のまま）
- 属性相性が計算順序に与える影響（コメント欄に未検証の指摘あり）
- 「掛け算パッシブ」の判別の例外（2015〜2016年の初期キャラなど）

## 8. 受け入れ基準

- (a) 手計算した期待値と一致する
- (b) 実機の被ダメージと近い値になる（実機検証後に確認）
- (c) 入力から結果表示までの操作回数が少ない

## 9. 非機能要件

- 対応ブラウザ: 最新のChrome・Safari
- オフライン対応: なし
- 保存するデータ: 前回の入力のみ、ブラウザ内（localStorage）に保存。外部には送信しない

## 10. 複数回の攻撃・積み上がるDEF効果の扱い

- 「これから上がる効果」の行を追加する方式で対応する（攻撃のたびの入力し直しは許容）
